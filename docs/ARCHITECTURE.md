# Архитектура приложения

Документ описывает, из каких слоёв состоит проект, как данные проходят от
схемы пользователя до графиков и почему приняты именно такие решения.

## 1. Общая картина

```
пользователь
    │  схема (вентили, измеряемые кубиты), параметры запуска
    ▼
┌─────────────────────────────────────────────────────────────────────┐
│ src.ui (Streamlit)                                                  │
│   architecture · circuit_editor · run_view · noise_view ·           │
│   experiments_view · help_view · state                              │
└───────────────┬─────────────────────────────────────────────────────┘
                │ Circuit, NoiseConfig, shots, seed
                ▼
┌─────────────────────────────────────────────────────────────────────┐
│ src.quantum (вычислительное ядро)                                    │
│   statevector → gates → circuit → noise → measurement → simulator   │
└───────────────┬─────────────────────────────────────────────────────┘
                │ SimulationResult (вероятности, частоты, состояние)
                ▼
┌─────────────────────────────────────────────────────────────────────┐
│ src.experiments                    │ src.render                      │
│   metrics · runner · export        │   charts · diagram · theme      │
└───────────────┬────────────────────┴──────────────┬──────────────────┘
                │ CSV                               │ PNG
                ▼                                   ▼
          файлы / download_button              st.image + download_button
```

Зависимости направлены только «вниз»: ядро не знает об интерфейсе,
эксперименты используют ядро, отрисовка не зависит от Streamlit. Поэтому
вычислительную часть можно тестировать и использовать как библиотеку.

## 2. Слои и модули

### 2.1. Вычислительное ядро `src/quantum`

| Модуль | Ответственность |
|---|---|
| `statevector.py` | Вектор состояния, нормировка, индексация кубитов, применение вентилей к одному состоянию и к пакету состояний |
| `gates.py` | Матрицы X, H, Z, CNOT и текстовые описания для интерфейса |
| `circuit.py` | `Operation`, `Circuit`, проверка корректности, слои/глубина, JSON |
| `noise.py` | `NoiseConfig`: каналы, вероятности, флаги, пояснения |
| `measurement.py` | Вероятности, обратное преобразование распределения, readout, частоты, генераторы случайных чисел |
| `simulator.py` | `run_circuit`: идеальное состояние, шумовые траектории, `SimulationResult` |

Ключевые интерфейсы:

```python
Circuit(n_qubits, operations=[Operation(gate="cnot", target=1, control=0)],
        measured_qubits=[0, 1])
circuit.validate()            # список ValidationIssue (error/warning)
circuit.depth()               # число слоёв операций

NoiseConfig(enabled=True, bit_flip_enabled=True, p_bit_flip=0.02)

result = run_circuit(circuit, shots=1000, seed=2024, noise=config)
result.ideal_probabilities    # теория (по измеряемым кубитам)
result.counts                 # частоты выбранного режима
result.probabilities_for("noisy")
```

### 2.2. Эксперименты `src/experiments`

| Модуль | Ответственность |
|---|---|
| `metrics.py` | TVD, вероятность цели, доля успешных запусков, среднее/стандартное отклонение/ДИ, таблицы |
| `runner.py` | Описание видов экспериментов, сборка серии, прогресс, агрегирование по повторам |
| `export.py` | DataFrame-представления, CSV с BOM для Excel, сохранение файлов |

`run_experiment(spec, progress=callback)` — единственная точка входа.
`ExperimentSpec.validate()` проверяет числа и не даёт запустить заведомо
слишком большую серию.

### 2.3. Отрисовка `src/render`

| Модуль | Ответственность |
|---|---|
| `theme.py` | Палитра, шрифты DejaVu (поставляются в `assets/fonts`), суперсэмплинг, вспомогательные примитивы |
| `charts.py` | Сгруппированная гистограмма, линейный график с доверительными интервалами и опорной линией |
| `diagram.py` | Изображение квантовой схемы (PNG) |

Схема логической архитектуры — готовое изображение
`assets/architecture.png`; раздел «Архитектура» показывает его и
пояснения к блокам.

Почему не Plotly/Matplotlib: приложение должно запускаться на любом ноутбуке
и в небольшом контейнере. Собственный рендерер на Pillow:

- не тянет тяжёлые зависимости (образ меньше, запуск быстрее);
- выдаёт ровно те байты PNG, которые сохраняет кнопка «Скачать PNG»;
- одинаково выглядит на Windows/Linux/macOS благодаря встроенному шрифту.

Плата — статичные графики вместо интерактивных; данные всё равно доступны в
таблицах и CSV.

### 2.4. Интерфейс `src/ui`

| Модуль | Раздел |
|---|---|
| `state.py` | состояние сессии, навигация, отложенные действия |
| `common.py` | заголовки, карточки метрик, экспорт, таблицы |
| `architecture.py` | «Архитектура» |
| `circuit_editor.py` | «Конструктор схем» |
| `run_view.py` | «Запуск и результаты» |
| `noise_view.py` | «Аппаратные ошибки» |
| `experiments_view.py` | «Эксперименты» |
| `help_view.py` | «Справка» |

#### Состояние сессии

Streamlit перезапускает скрипт при каждом действии, поэтому всё, что должно
пережить перерисовку, хранится в `st.session_state`:

- `circuit` — объект `Circuit` (изменяется через методы, а не пересоздаётся);
- `noise` — `NoiseConfig`;
- `shots`, `seed`, `target` — параметры запуска;
- `result`, `result_signature` — последний запуск и его отпечаток;
- `experiment_result` — последняя серия;
- `notice` — сообщение для следующей перерисовки.

Чтобы не нарушать правило Streamlit «нельзя менять значение виджета после его
создания», действия, которые меняют виджеты (загрузка демо-схемы, переход в
раздел), сначала складываются в `_pending_action`, а применяются в начале
следующего запуска (`apply_pending_action`).

#### Актуальность результата

`run_signature(circuit, noise, shots, seed)` собирает строковый отпечаток
параметров. Если пользователь изменил схему или настройки, страница
результатов предупреждает, что показан прежний расчёт.

## 3. Поток выполнения

1. `Circuit.validate()` проверяет индексы, CNOT, измеряемые кубиты.
2. `build_ideal_state()` последовательно применяет матрицы вентилей.
3. `marginal_probabilities()` оставляет только измеряемые кубиты.
4. `sample_outcomes()` разыгрывает `shots` исходов по кумулятивному
   распределению (обратное преобразование).
5. Если включён режим ошибок, `_simulate_trajectories()` строит пакет из
   `shots` состояний, применяет к ним вентили и случайные X/Z-ошибки, затем
   измеряет каждую траекторию и применяет readout.
6. `metrics_for_result()` считает TVD, вероятность цели и шумовой уровень.
7. Интерфейс рисует PNG и таблицы; экспорт формирует CSV.

## 4. Производительность

- Вектор состояния — `complex128`, 16 байт на амплитуду: 5 кубитов — 512 Б,
  10 кубитов — 16 КБ.
- Шумовые траектории обрабатываются пакетом `(shots, 2^n)`: вместо цикла на
  Python по каждому измерению выполняется несколько векторных операций.
  Один запуск 1000 shots на 5 кубитах занимает ~1 мс.
- Серия из 630 запусков (3 канала × 21 точка × 10 повторов) выполняется
  меньше секунды на обычном CPU.
- Перед запуском `_check_memory()` оценивает объём (`shots × 2^n × 16` байт)
  и отклоняет заведомо невыполнимые комбинации с понятным сообщением.
- Длительные операции (серия экспериментов) показывают прогресс-бар и
  вызывают обновление интерфейса по ходу выполнения.

## 5. Обработка ошибок

- Проверки параметров поднимают `ValueError` с русским текстом;
- интерфейс перехватывает ошибки запуска и серии и показывает `st.error`,
  не завершая приложение;
- глобальный обработчик в `app.py` не даёт странице «упасть» с трейсбеком:
  показывает сообщение и раскрывающийся блок с деталями;
- файлы схем проверяются при загрузке (`Circuit.from_dict`), повреждённый
  JSON объясняется пользователю;
- если каталог `examples` недоступен, приложение стартует с встроенной
  схемой Белла.

## 6. Тестируемость

- `tests/` — 143 теста на `unittest` (совместим с pytest), включая
  независимую эталонную реализацию вентилей и шумовых траекторий;
- `tools/ui_check.py` подменяет Streamlit заглушкой и отрисовывает все
  разделы, проверяя, что кнопки и переходы действительно меняют состояние;
- `tools/app_test.py` запускает приложение в настоящем рантайме Streamlit
  (`st.testing.v1.AppTest`): проходит по всем разделам, загружает демо-схему,
  выполняет запуски и серию экспериментов, проверяя отсутствие исключений.
- примеры результатов генерируются скриптом `scripts/generate_examples.py`,
  поэтому CSV и PNG в `examples/results` — реальные расчёты.

## 7. Как расширять

- **Новый вентиль.** Добавить матрицу и описание в `gates.py` (для
  двухкубитного — ветку в `apply_gate_to_array`), обновить таблицу в
  «Справке».
- **Новый шумовой канал.** Добавить поля в `NoiseConfig`, применить канал в
  `_simulate_trajectories`, описать в `CHANNEL_INFO`.
- **Новый эксперимент.** Добавить `ExperimentKindInfo` в
  `EXPERIMENT_KINDS`, ветку построения серии в `run_experiment`, элемент
  выбора в интерфейсе.
- **Другой способ визуализации.** `src/render` возвращает PNG-байты, поэтому
  его можно заменить, не затрагивая ядро и эксперименты.
